# bangla-news-24-app

Bengali-language news reader: Next.js 16 App Router, React 19, TypeScript, Tailwind v4 + daisyUI. UI copy and most code comments are Bengali — keep new user-facing strings in Bengali. `CLAUDE.md` just imports this file.

## Commands (npm; `package-lock.json` is the lockfile)

- `npm run dev` / `npm run build` / `npm start`
- `npm run lint` — runs bare `eslint` over the whole repo (flat config in `eslint.config.mjs`)
- `npx tsc --noEmit` — the only typecheck; there is no `typecheck` script
- No test runner exists (no test script, no Jest/Vitest/Playwright). Don't invent one unless asked.

`npm run lint` and `npx tsc --noEmit` currently fail on pre-existing issues in files unrelated to most changes: `no-explicit-any` in `src/app/category/[categoryId]/page.tsx` and `src/app/news/[newsId]/page.tsx`, implicit `any` + `callBackURL` typo in `src/app/signup/page.tsx`, and a duplicate `News` interface mismatch between `category/[categoryId]` and `NewsCard`. Confirm a failure predates your edit before fixing or blaming it.

## Data flow

- All content comes from the public API `https://news-api-v2.vercel.app`, hardcoded at every call site — no shared client, base-URL constant, or env var. Endpoints in use: `api/news/sections` (`src/app/page.tsx`), `api/news?limit=10` (`Marquee`), `api/news/most-read` (`MostRead`), `api/categories` (`Navlinks`), `api/news/category/:categoryId` (`category/[categoryId]`), `api/article/:id` (`news/[newsId]`). Changing the host means editing all six.
- Every page/component is an async Server Component fetching with `cache: "no-store"` (except the article detail fetch, which uses the default), and every data fetch is wrapped in try/catch that renders an empty/loading state — preserve that, since the external API is intermittently unreachable.
- Response shapes differ per endpoint (`{ data: ... }` wrapper vs bare array vs `data.title`), and `Article`/`Section`/`News`/`NewsItem`/`NewsData` are re-declared locally in each file rather than shared. Match the endpoint you touch instead of importing types.

## Auth (better-auth + MongoDB)

- Server config `src/lib/auth.ts`: db name `bangla-news-24-app` is hardcoded, `MONGODB_URI` comes from env. Browser client `src/lib/auth-client.ts`. `src/app/api/auth/[...all]/route.ts` is generated by `toNextJsHandler` — don't hand-edit it.
- Only signup is wired (`authClient.signUp.email`). `src/app/signin/page.tsx` is UI with no submit handler, and `/dashboard` (the signup redirect target) does not exist.
- Import the browser client from `better-auth/react`. `better-auth/solid` pulls in `solid-js` (not installed) and breaks compilation of every route, not just signup.
- `src/lib/auth-client.ts` reads `process.env.BETTER_AUTH_URL`, which is `undefined` in the browser (only `NEXT_PUBLIC_*` is inlined), so requests default to the current origin + `/api/auth`.
- `.env` is gitignored and needs `MONGODB_URI`, `BETTER_AUTH_URL`, `BETTER_AUTH_SECRET`. Without them the auth route fails at request time.

## Gotchas

- Next 16 async `params`: `const { newsId } = await params` (see both dynamic routes).
- `next/image` remote hosts are allowlisted in `next.config.ts` (only `ichef.bbci.co.uk`). Images from any other news source throw until the hostname is added to `remotePatterns`.
- Tailwind v4 + daisyUI v5 are configured entirely in `src/app/globals.css` (`@import "tailwindcss"; @plugin "daisyui";`). There is no `tailwind.config.*`; theme is set via `data-theme="light"` on `<html>`.
- React Compiler is enabled in `next.config.ts`; don't add manual `useMemo`/`useCallback` memoization passes to satisfy it.
