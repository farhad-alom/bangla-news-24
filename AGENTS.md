# bangla-news-24-app

Bengali-language news reader: Next.js 16 App Router, React 19, TypeScript, Tailwind v4 + daisyUI. UI copy and most code comments are Bengali — keep new user-facing strings in Bengali. `CLAUDE.md` just imports this file.

## Commands (npm; `package-lock.json` is the lockfile)

- `npm run dev` / `npm run build` / `npm start`
- `npm run lint` — runs bare `eslint` over the whole repo (flat config in `eslint.config.mjs`)
- `npx tsc --noEmit` — the only typecheck; there is no `typecheck` script
- No test runner exists (no test script, no Jest/Vitest/Playwright). Don't invent one unless asked.

Both `npm run lint` and `npx tsc --noEmit` currently pass — keep them green; there is no CI, so run them yourself before claiming a change is done.

## Data flow

- All content comes from the public API `https://news-api-v2.vercel.app`, hardcoded at every call site — no shared client, base-URL constant, or env var. Endpoints in use: `api/news/sections` (`src/app/page.tsx`), `api/news?limit=10` (`Marquee`), `api/news/most-read` (`MostRead`), `api/categories` (`Navlinks`), `api/category/:slug` (`category/[categoryId]`), `api/article/:id` (`news/[newsId]`). Changing the host means editing all six. Note `api/category/:slug` is the category endpoint — `api/news/category/:slug` returns 404.
- Every page/component is an async Server Component fetching with `cache: "no-store"` (except the article detail fetch, which uses the default), and every data fetch is wrapped in try/catch that renders an empty/loading state — preserve that, since the external API is intermittently unreachable.
- Response shapes differ per endpoint (`{ data: ... }` wrapper vs bare array vs `data.title`), and `Article`/`Section`/`News`/`NewsItem`/`NewsData` are re-declared locally in each file rather than shared. Match the endpoint you touch instead of importing types.
- Article `id` is **not always a route id**: `api/news/sections` includes social-promo items (`type: "link"`) whose `id` is a URL-encoded external URL, and `most-read` can return a UUID that `api/article/:id` rejects. Route every article/news link through `src/components/ArticleLink.tsx` (`src/lib/article-link.ts`) — it emits `/news/:id` for real BBC ids and an external `target="_blank"` link otherwise. Never hand-build `/news/${id}`.

## Auth (better-auth + MongoDB)

- Flow: `src/app/signup/page.tsx` and `src/app/signin/page.tsx` are client components calling `authClient.signUp.email` / `authClient.signIn.email`, then `router.push("/")` + `router.refresh()`. `src/components/AuthButtons.tsx` (client, `authClient.useSession()`) owns the header's signed-in/out state and sign-out. `Header.tsx` must stay a Server Component — it imports the async server component `Navlinks`, so don't convert it to `"use client"`.
- `src/lib/auth.ts`: validates `MONGODB_URI` and `BETTER_AUTH_SECRET` at import time, reuses a single `MongoClient` via `globalThis.__mongoClient` (dev HMR would otherwise leak connections), db name `bangla-news-24-app`. Collections: `user`, `account`, `session`.
- Password hashing/verification is better-auth's built-in scrypt (`account.password`, 161-char hash, `providerId: "credential"`). Do not add custom hashing or store plaintext; `emailAndPassword.minPasswordLength` is 8 (server-enforced as `PASSWORD_TOO_SHORT`).
- Error copy lives in `src/lib/auth-errors.ts`, which maps codes (`INVALID_EMAIL_OR_PASSWORD`, `PASSWORD_TOO_SHORT`, `USER_ALREADY_EXISTS_USE_ANOTHER_EMAIL`, `VALIDATION_ERROR`, `INVALID_ORIGIN`) to Bengali and hides raw English/network text. Add new codes there, not inline in pages; client-side pre-checks (email shape, password length, confirm match) run before the request.
- Env: `.env` is gitignored (template: `.env.example`) and needs `MONGODB_URI`, `BETTER_AUTH_URL` (server), `BETTER_AUTH_SECRET`. Only `NEXT_PUBLIC_BETTER_AUTH_URL` reaches the browser and it is optional — without it the client targets the current origin + `/api/auth`.
- Node on this machine cannot resolve Atlas SRV records (`querySrv ECONNREFUSED`, though Windows DNS resolves them), so `.env` uses the direct-seed form `mongodb://user:pass@host0,host1,host2:27017/?ssl=true&authSource=admin`. Prefer `mongodb+srv://` wherever SRV lookup works.
- `src/app/api/auth/[...all]/route.ts` is generated by `toNextJsHandler` — don't hand-edit. Sessions are cookie-based (`better-auth.session_token`, HttpOnly, SameSite=Lax, 7-day expiry).

## Gotchas

- Next 16 async `params`: `const { newsId } = await params` (see both dynamic routes).
- `next/image` remote hosts are allowlisted in `next.config.ts` (only `ichef.bbci.co.uk`). Images from any other news source throw until the hostname is added to `remotePatterns`.
- Tailwind v4 + daisyUI v5 are configured entirely in `src/app/globals.css` (`@import "tailwindcss"; @plugin "daisyui";`). There is no `tailwind.config.*`; theme is set via `data-theme="light"` on `<html>`.
- React Compiler is enabled in `next.config.ts`; don't add manual `useMemo`/`useCallback` memoization passes to satisfy it.
